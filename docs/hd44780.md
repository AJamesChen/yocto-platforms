# HD44780 character LCD

The Raspberry Pi 4B image includes libgpiod 2.1.3 and its command-line tools.
This procedure verifies a bare 16-pin HD44780-compatible character display in
4-bit parallel mode. It was tested on the project image with `gpiochip0`
provided by the BCM2711 pin controller.

An LCD fitted with an I2C backpack uses a different interface and is not
covered by this test.

## Wiring

Power off the Raspberry Pi before changing the wiring.

| LCD pin | Function | Raspberry Pi GPIO | Physical pin |
| --- | --- | --- | --- |
| 1 | VSS | Ground | 6 |
| 2 | VDD | 5 V | 2 or 4 |
| 3 | VO | 10 kOhm contrast potentiometer wiper | — |
| 4 | RS | GPIO25 | 22 |
| 5 | R/W | Ground | 6, 9, 14, 20, 25, 30, 34, or 39 |
| 6 | E | GPIO24 | 18 |
| 7–10 | D0–D3 | Not connected | — |
| 11 | D4 | GPIO23 | 16 |
| 12 | D5 | GPIO17 | 11 |
| 13 | D6 | GPIO18 | 12 |
| 14 | D7 | GPIO22 | 15 |
| 15 | LED A | 5 V through a suitable resistor if required | 2 or 4 |
| 16 | LED K | Ground | 6, 9, 14, 20, 25, 30, 34, or 39 |

Connect the two ends of the contrast potentiometer to 5 V and ground. Keeping
R/W grounded prevents the 5 V LCD from driving its data pins into the Pi.

GPIO25 is also the reset signal used by this project's MFRC522 tool. Do not run
the LCD test and `mfrc522-tool` at the same time with this wiring. Move one of
the signals to another free GPIO if both peripherals must operate concurrently.

The Pi outputs 3.3 V logic. Many 5 V LCD modules accept this as high, but it is
not guaranteed for every HD44780-compatible controller. Use a 3.3-to-5 V level
shifter on RS, E, and D4–D7 if the module's input thresholds require it.

## Verify libgpiod and GPIO availability

After booting the updated image, connect over SSH and confirm the installed
tool version and GPIO controller:

```sh
ssh root@PI_ADDRESS
gpioset --version
gpiodetect
```

With libgpiod 2.x, pass the chip to `gpioinfo` with `-c`:

```sh
gpioinfo -c gpiochip0 | grep -E 'line +(17|18|22|23|24|25):'
```

The direction may be `input` or `output`. A line is available when it has no
`consumer="..."` field. The test will fail rather than take a line already held
by another process.

## Run the display test

From the project checkout on the development host, copy the helper to the Pi:

```sh
scp scripts/test-hd44780-rpi4b.sh root@PI_ADDRESS:/tmp/
ssh root@PI_ADDRESS /tmp/test-hd44780-rpi4b.sh
```

The display should show `LCD TEST OK` for 30 seconds. Pass a different gpioset
period to change how long the test holds the GPIO lines:

```sh
ssh root@PI_ADDRESS /tmp/test-hd44780-rpi4b.sh 2m
```

While the test runs, a second SSH session can confirm ownership:

```sh
gpioinfo -c gpiochip0 | grep hd44780
```

## Troubleshooting

- Backlight on, no visible characters: slowly adjust the contrast
  potentiometer.
- One or two rows of solid blocks: the LCD has power and contrast but did not
  initialize; check RS, E, D4–D7, and the common ground.
- Completely blank display: verify VDD, VSS, VO, and the backlight connections.
- `Device or resource busy`: use `gpioinfo -c gpiochip0` to find the process
  holding a required line. In particular, stop MFRC522 access before using
  GPIO25 for the LCD.
- Correct wiring but no initialization: check whether the LCD needs a logic
  level shifter for reliable 3.3 V high levels.
